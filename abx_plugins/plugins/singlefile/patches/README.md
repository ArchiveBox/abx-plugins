# Temporary SingleFile font processing fixes

The source excerpt and patch in this directory are derived from
[single-file-core](https://github.com/gildas-lormeau/single-file-core), commit
`79ecf4dce4acab130c0b587d8843f0328eb389f9`,
[`core/lib/processor-helper-common.js`](https://github.com/gildas-lormeau/single-file-core/blob/79ecf4dce4acab130c0b587d8843f0328eb389f9/core/lib/processor-helper-common.js).

Modified 2026-11-07: reuse the CSS value already generated by `getPropertyValue`
instead of serializing the selected value twice; use nested exact-string Maps
for scope/descriptor and source keys rather than concatenating full font data
into duplicate-rule keys; cache repeated source parsing for one pass. String
coercion and source equality are preserved.
The readable changes are in
`font-serialization.patch`; the preparation hook carries the exact original
and modified methods plus original/patched bundle hashes. These first three
optimizations do not change font selection or capture options.

## Temporary compatibility restriction

The preparation hook and `singlefile_extension_save.js` capture guard require
reviewed SingleFile 1.36.0 and the exact prepared bundle hash. Unprepared,
changed, or future unreviewed versions fail SingleFile clearly before capture;
other plugins and Chrome startup retain their existing behavior. Remove both
the preparation hook and this guard when adopting a validated upstream fix.

The third change caches source splitting and parsed font metadata by exact string
equality for one font-processing pass, including nested scopes and stylesheets.
Each rule receives a fresh array and metadata record; validity mutations remain
independent. Regular expressions, fallback order, source selection, and embedded
font bytes are unchanged. These caches are released at the end of the pass.

The corresponding-source diff uses zero-context unified hunks to preserve
upstream tab indentation without whitespace-tool ambiguity. Apply it to the
exact upstream commit with `git apply --unidiff-zero font-serialization.patch`.

Three separate test-only readable patches modify `processFontFaceRule` in the
[inline helper](https://github.com/gildas-lormeau/single-file-core/blob/79ecf4dce4acab130c0b587d8843f0328eb389f9/core/lib/processor-helper-inline.js),
under the same original copyright/license notice above:

1. `timer-repair.patch` clears the existing primary/fallback timer when its
   load rejects. A rejected font must not later become accepted merely because
   its abandoned timer fires while another source is loading.
2. `primary-cache-only.patch` caches the primary exact-source outcome, not the
   final rule-specific fallback result. Other rejection resolves the original
   URL through the current rule's actual AST node; that contextual fallback is
   not cached. A successful fallback for one rule cannot contaminate another.
3. `corrected-lazy.patch` validates priority formats in the original selector's
   order, including reverse-order ties, then all tech sources and any generic
   fallback candidates required by that selector. The final selector, local
   entries, retained order, statistics, reversal and serialization are unchanged.

reintroduced based on the metadata benchmark alone.


## CSS-tree token storage correctness (2026-11-09)

SingleFile 1.36.0 packs token types and end offsets into 32-bit words with a
27-bit offset. CSS reaching 134,217,728 UTF-16 code units wraps offsets and can
make parsing fail to advance. The old buffers also allocate one entry per
source character, even when one large data URL contains most of the source.

`css-tree/TokenStream.js` and `css-tree/TokenStream.patch` provide readable source
and the diff against official @eslint/css-tree 4.1.1 TokenStream.js, SHA256
`9d1b0b5e157a984b2700b75a2a44b63dae4ab426186f4d94d3aff2436967d0ec`.
This copied/modified tokenizer is MIT licensed, copyright Roman Dvornov and
OpenJS Foundation contributors; its complete notice is in `css-tree/LICENSE`.
The parent extension and common-helper modifications retain their AGPL license.
`css-tree/build.js` and `css-tree/build.patch` are the corresponding source
build overlay and diff for single-file-core's AGPL-licensed build script.
The overlay rejects dependency source drift and fails if it was not applied;
it preserves the existing URL encode/decode patches.

The exact pinned production bundle replaces only its 3,557-byte TokenStream
class with the reviewed 4,212-byte class. Every other byte after the common stage,
including the native font validator, stays unchanged. The hook verifies the
original bundle, common stage, unique class anchor and final bundle hashes.
No runtime source download or rebuild occurs in preparation.

Token words use exact Float64 arithmetic for a type plus a full Uint32 offset.
Buffers grow geometrically by actual token count, including the EOF sentinel.
Every used balance entry is assigned; the root sentinel never reads a stale
reused token. Grammar, tokenizer callbacks, URL decoding and AST output are
unchanged. Dense token storage costs 12 bytes per capacity entry instead of 8,
a real 50% dense-buffer premium; growth temporarily retains old and new arrays.
Sparse large styles avoid the old source-length allocation. This is not a
universal memory reduction claim.

Regression tests run the actual pinned parser with synthetic valid CSS crossing
128 MiB, differential token-stream API and reuse checks, and exact generated CSS.
No saved public or private capture is included. Offline parser correctness does
not establish live Canva timing or complete capture/render fidelity; native
capture and normal gallery acceptance remain required before release.
